# Samsung TV IR Codes

## Angela's Samsung TV (tested 2026-06-15)

**Protocol:** NEC, 8-bit address (NOT complemented — both bytes identical)
**Address:** 0x07 (both bytes are 0x07, not 0x07/0xF8)
**Power toggle function:** 0x02 (complement 0xFD)
**Frequency:** ~38kHz

### Key findings
- The stock remote has a SINGLE power toggle button (function 0x02)
- **No discrete power on/off codes exist** for this TV
- Generated discrete codes were tested:
  - Address 0x07, function 0x02 = toggle (same as stock remote)
  - Address 0x07, function 0x03 = **timer function**, NOT power off
  - Address 0xE0E0, function 0x02 = toggle
  - Address 0xE0E0, function 0x03 = toggle (required sending twice)
- **Conclusion:** Use a single "Samsung TV Power Toggle" virtual device with the toggle code

## Samsung NEC Protocol Reference

Samsung uses two NEC address variants:
- **8-bit address (older):** 0x07 — both bytes identical, NOT complemented
- **16-bit address (newer):** 0xE0E0 — standard NEC complemented

Many Samsung TVs respond to BOTH address variants.

### Standard Samsung function codes (0xE0E0 address)
| Function | Code | Notes |
|---|---|---|
| Power toggle | 0xBF | What most stock remotes send |
| Volume Up | 0xE0 | |
| Volume Down | 0x10 | |
| Mute | 0xF0 | |

### Discrete power codes (0xE0E0 address, not all TVs support)
| Function | Code | Notes |
|---|---|---|
| Power ON | 0x02 | Not universal — test first |
| Power OFF | 0x03 | Not universal — test first |

## Broadlink Code Format

Two incompatible formats exist:
1. **Base64** (used by Home Assistant integration, GitHub gists): `JgBGA...`
2. **Raw hex** (used by Hubitat Broadlink driver): `26008C00...`

The Hubitat Broadlink driver uses **raw hex format**. Codes from community databases (gist.github.com/flowolf) are in base64 and CANNOT be used directly — they must be converted or the codes must be re-learned.

### Raw hex format structure
```
26 00           — fixed header
XX YY           — number of burst pairs (little-endian 16-bit)
[mark space]    — burst pairs (each 2 bytes: mark duration, space duration)
00 00           — end of pairs (trailer)
[repeat frame]  — optional NEC repeat frame
00 00 ...       — padding
```
Each byte value × ~26.9µs = actual timing in microseconds.

### NEC timing (in raw hex units)
- Header mark: ~0x90 (3840µs) / space: ~0x8F (3830µs)
- Data mark: ~0x12 (432µs) for all bits
- Space for '0': ~0x12 (432µs, short)
- Space for '1': ~0x36 (900µs, long)
- Bit threshold: 0x20 (space > 0x20 = bit 1)

## Generating Discrete Codes from Toggle

If a Samsung TV only has a toggle code, discrete on/off codes can be GENERATED by modifying the function byte in the raw hex. Samsung NEC protocol:

- Address bytes: NOT complemented (both bytes are the same value)
- Function bytes: complemented (byte 3 = ~byte 2)
- To change the function: replace pairs 17-24 (function) and 25-32 (complement) in the burst pair data

**Caveat:** Generated codes may not work if the TV doesn't support the target function code. Always test — if the generated code does something unexpected (e.g., timer instead of power off), that function code is mapped to a different button on the TV.

## Samsung TV WebSocket API (tested 2026-06-15)

Angela's Samsung TV at 192.168.0.135 was tested with the Samsung WebSocket API. Results:

- **Port 8001, `samsung.remote.control` channel**: Returns `ms.channel.unauthorized`. Requires a pairing token from prior authorization. No permission popup appears — the TV rejects the connection immediately. This is the standard Tizen v2 API channel but needs first-time pairing.
- **Port 8002 (SSL), `ms.remote.control` channel**: Connects successfully and accepts the WebSocket session. However, the TV rejects `ms.remote.control` as a method name with `"unrecognized method value : ms.remote.control"`. This means the TV does NOT support the Tizen v2 WebSocket API on this channel.
- **Port 8002 (SSL), `samsung.remote.control` channel**: Connection times out (no response).

**Conclusion:** This Samsung TV model does not support the standard Samsung WebSocket remote control API without prior token-based pairing. The IR toggle via Broadlink is the reliable control method.

**For other Samsung TVs that DO support the API**, the correct flow is:
1. Connect to `ws://<ip>:8001/api/v2/channels/samsung.remote.control?name=<base64_name>`
2. TV shows permission popup, user accepts
3. Response includes a token in `data.token` — save it for future connections
4. Send commands with method `ms.remote.control` and params `{Cmd: "Click", DataOfCmd: "KEY_POWER", TypeOfRemote: "SendRemoteKey", Option: "false"}`
