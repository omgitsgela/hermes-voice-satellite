MODEL-PIN-ADDENDUM.TXT; current installed pin state is recorded in section 4)

1) HOW THE SATELLITE SELECTS ITS MODEL AND REASONING AT THE API
The satellite sends its durable pin (voice-model.json at the project root) on
every POST /v1/runs request as model / provider / model_options /
require_model_lock. The Hermes API gateway translates the request's
model_options into the agent's reasoning config via
gateway/platforms/api_server.py _request_reasoning_config():
  - model_options.reasoning_effort accepts: none (aliases false/disabled, or
    JSON boolean false), minimal, low, medium, high, xhigh, max, ultra.
  - "none" becomes {"enabled": false} = thinking OFF for that session.
  - When the request carries a valid reasoning selection it OVERRIDES the
    gateway's global agent.reasoning_effort (config.yaml) for that session.
    The global value still applies to every other surface (Desktop, CLI, etc.).
This means reasoning for voice can be tuned per-satellite by editing
voice-model.json ONLY - no Hermes core code change and no global config
change is needed, and other chats are unaffected.
Known limit (verified in source): if a mid-turn fallback swap activates,
chat_completion_helpers re-resolves reasoning_config for the fallback model
from config.yaml (per-model reasoning_overrides > global reasoning_effort).
The per-request "none" does not follow the session into the fallback model.
Making reasoning satellite-only for the fallback too would require a Hermes
core change; it was deliberately NOT done. config.yaml was NOT touched.

4) VOICE ANSWER BEHAVIOR: "ONE MOMENT." VS IMMEDIATE ANSWER
Host users may notice the satellite sometimes says "One moment." before an
answer and sometimes answers directly. This is the satellite gateway's
silence filler (satellite_gateway/loop.py):
- Triggers on EITHER: (a) the run starts using a tool (on_tool_started from
  /v1/runs events), or (b) 4 seconds pass (SILENCE_FILLER_SECONDS) with
  nothing spoken yet - a slow first token gets the filler just like a tool
  call.
- Spoken at most once per turn and only before the first real sentence; the
  timer is cancelled as soon as the model starts streaming.
- Turns answered locally without reaching the model (volume commands,
  "new conversation" reset phrases, rejected blips) never use the filler;
  they get instant canned replies.
- The Gateway (not the satellite) owns the "thinking" LED phase because the
  satellite cannot tell the filler from the answer (both arrive as
  AudioStart); the violet busy LED stays on through filler + tool work until
  the answer starts playing.
- Total gateway failure instead of silence produces the spoken fallback
  "I can't reach my brain right now" (see
  RESTART-AND-RECOVERY-VERIFICATION.TXT root-cause notes).

5) HOW TO CHANGE REASONING YOURSELF (safe procedure)
1. Edit only voice-model.json: set model_options.reasoning_effort to
   "none" (off), or one of minimal/low/medium/high/xhigh/max/ultra. Keep
   provider explicit. Invalid/unknown pins fail closed loudly.
2. Planned stop: create <project>/state/windows-supervisor.stop, wait for
   the owned children/listeners to disappear and the HermesVoiceSatellite
   task to reach Ready.
3. Remove the sentinel, then Start-ScheduledTask HermesVoiceSatellite.
   (Never use Task Scheduler "End" as the planned stop - job containment
   kills children abruptly.)
4. Verify: verify_voice_backend.py, agent.log conversation-turn line,
   fleet_status convergence. A restart IS required; editing the JSON alone
   does not update the running client.
5. This file only affects the satellite voice session. Do not set a global
   model pin or global reasoning change to tune the satellite - that would
   change Desktop and every other chat too.
